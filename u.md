# Разбор ноутбука `plot_ssim.ipynb`

## Общая суть

Ноутбук демонстрирует разницу между двумя метриками похожести изображений:

1. **MSE** (Mean Squared Error, среднеквадратичная ошибка) — простая метрика, которая считает среднее квадратов разностей пикселей.
2. **SSIM** (Structural Similarity Index, индекс структурного сходства) — более «умная» метрика, которая учитывает структуру, контраст и яркость, а не только попиксельную разницу.

**Главная идея:** MSE может показывать одинаковую «ошибку» для двух совершенно разных искажений, а SSIM — нет. SSIM лучше согласуется с тем, как человек воспринимает изображения.

### Ячейка 2 (Код)

Разберём по блокам:

#### 1. Импорты
```python
import numpy as np
import matplotlib.pyplot as plt
from skimage import data, img_as_float
from skimage.metrics import structural_similarity as ssim
from skimage.metrics import mean_squared_error
```
- `numpy` — работа с массивами (изображение = массив чисел).
- `matplotlib` — построение графиков.
- `skimage` (scikit-image) — библиотека для обработки изображений. Из неё берём:
  - `data.camera()` — стандартное тестовое изображение (фото оператора с камерой).
  - `img_as_float` — приводит картинку к типу float в диапазоне [0, 1].
  - `ssim` — функция для подсчёта индекса структурного сходства.
  - `mean_squared_error` — функция для подсчёта MSE.

#### 2. Загрузка изображения
```python
img = img_as_float(data.camera())
rows, cols = img.shape
```
- Загружаем картинку и превращаем в числа с плавающей точкой.
- `rows, cols` — размеры (высота, ширина). В коде они дальше не используются, но сохранены «на всякий случай».

#### 3. Создание шума
```python
noise = np.ones_like(img) * 0.2 * (img.max() - img.min())
rng = np.random.default_rng()
noise[rng.random(size=noise.shape) > 0.5] *= -1
```
- Создаётся массив `noise` того же размера, что и картинка, заполненный значением `0.2`.
- Затем примерно в половине пикселей знак меняется на минус (случайно). Получается **шум ±0.2**: где-то +0.2, где-то −0.2.
- `rng` — генератор случайных чисел (новый стиль в numpy).

#### 4. Два искажения
```python
img_noise = img + noise
img_const = img + abs(noise)
```
- `img_noise` — к оригиналу прибавили **случайный** шум ±0.2 (пиксели «дрожат»).
- `img_const` — к оригиналу прибавили **постоянную** добавку +0.2 (картинка стала ярче).

Оба изображения дают **одинаковый MSE** — ведь величина добавки по модулю везде одна и та же (0.2). Но визуально они отличаются сильно.

#### 5. Подсчёт метрик
```python
mse_none = mean_squared_error(img, img)
ssim_none = ssim(img, img, data_range=img.max() - img.min())

mse_noise = mean_squared_error(img, img_noise)
ssim_noise = ssim(img, img_noise, data_range=img_noise.max() - img_noise.min())

mse_const = mean_squared_error(img, img_const)
ssim_const = ssim(img, img_const, data_range=img_const.max() - img_const.min())
```
- Для каждого изображения считается MSE и SSIM относительно оригинала.
- `data_range` — разброс значений (max − min). SSIM требует этот параметр, потому что работает с яркостью и контрастом.
- **MSE**: 0 для оригинала, одинаковый для `img_noise` и `img_const`.
- **SSIM**: 1.0 для оригинала, высокий для `img_const` (структура сохранилась, просто сдвинулась яркость) и низкий для `img_noise` (структура разрушена шумом).

#### 6. Визуализация
```python
fig, axes = plt.subplots(nrows=1, ncols=3, figsize=(10, 4), sharex=True, sharey=True)
ax = axes.ravel()

ax[0].imshow(img, cmap=plt.cm.gray, vmin=0, vmax=1)
ax[0].set_xlabel(f'MSE: {mse_none:.2f}, SSIM: {ssim_none:.2f}')
ax[0].set_title('Original image')
...
plt.tight_layout()
plt.show()
```
- Рисуется 3 картинки в один ряд:
  1. Оригинал
  2. С шумом (`img_noise`)
  3. С постоянной добавкой (`img_const`)
- Под каждой — подпись с MSE и SSIM.
- `cmap=plt.cm.gray` — отображение в оттенках серого.
- `vmin=0, vmax=1` — фиксированный диапазон яркости (иначе matplotlib автоматически растянет контраст, и сравнение будет некорректным).
- `sharex=True, sharey=True` — общие оси (чтобы картинки были выровнены).
- `plt.tight_layout()` — автоматическая подгонка отступов.

## Что мы видим на графике

На выходе — **три изображения в ряд** (см. картинку в ноутбуке):

| Изображение | MSE | SSIM | Что видно |
|---|---|---|---|
| Оригинал | 0.00 | 1.00 | Чёткое фото оператора |
| С шумом | ~0.04 | ~0.30 | «Соль и перец», зернистость, структура разрушена |
| С постоянной добавкой | ~0.04 | ~0.90 | Картинка просто светлее, но структура сохранена |

**Ключевой момент:** MSE у второго и третьего изображения **одинаковый** (около 0.04), но SSIM различается в разы. Это и есть главная демонстрация: MSE не различает «типы» ошибок, а SSIM — да.

**Почему так?**
- MSE считает **квадрат разности** в каждой точке. Если вы сдвинули яркость на +0.2 везде — в каждой точке разность 0.2, квадрат 0.04, среднее 0.04. Если шум ±0.2 — тоже средний квадрат 0.04 (потому что 0.2² = 0.04). Математически одинаково.
- SSIM сравнивает **локальные статистики** (среднее, дисперсию, ковариацию) в скользящем окне. При постоянной добавке структура (ковариация) сохраняется, меняется только яркость — SSIM остаётся высоким. При шуме структура разрушается — SSIM падает.

## Какие параметры можно менять и что будет

### 1. Величина шума
```python
noise = np.ones_like(img) * 0.2 * (img.max() - img.min())
```
- **Увеличить** (например, 0.5) → шум станет сильнее, SSIM упадёт ещё ниже, MSE вырастет. Картинка станет почти неразборчивой.
- **Уменьшить** (например, 0.05) → шум почти незаметен, SSIM будет близок к 1, MSE — к 0.

### 2. Доля «перевёрнутых» пикселей
```python
noise[rng.random(size=noise.shape) > 0.5] *= -1
```
- **Заменить 0.5 на 0.9** → почти все пиксели получат −0.2 (только 10% останутся +0.2). Это уже ближе к постоянному сдвигу, SSIM подрастёт.
- **Заменить на 0.1** → почти все +0.2, тоже ближе к постоянному сдвигу.

### 3. Величина постоянной добавки
```python
img_const = img + abs(noise)
```
- `abs(noise)` — это всегда +0.2. Можно заменить на `+ 0.5` — картинка станет ещё светлее, MSE вырастет, SSIM немного упадёт (яркость сильно ушла), но всё равно будет выше, чем у шумной.

### 4. Размер окна SSIM
```python
ssim(img, img_noise, data_range=...)
```
У `ssim` есть параметр `win_size` (по умолчанию 7). Можно передать, например, `win_size=11`:
- Больше окно → SSIM «усредняется» сильнее, становится менее чувствителен к мелким деталям.
- Меньше окно → SSIM более локальный, чувствительнее к мелким искажениям.

### 5. Тип шума
Можно заменить случайный шум на:
- **Гауссов шум**: `rng.normal(0, 0.1, img.shape)` — более реалистичный.
- **Соль и перец** (крайние значения 0 и 1).
- **Размытие** (Gaussian blur) — SSIM хорошо ловит потерю резкости.

### 6. `data_range`
```python
data_range=img.max() - img.min()
```
- Можно задать вручную, например `1.0`, если точно знаете, что картинка в [0, 1].
- Если `data_range` занизить, SSIM будет «переоценивать» схожесть; завысить — «недооценивать».

### 7. Само изображение
Вместо `data.camera()` можно взять `data.astronaut()`, `data.coffee()` и т.д. На цветных картинках SSIM считается по каждому каналу отдельно (или по яркости).

## Итог

- **MSE** — простая, но «слепая» к типу искажения метрика.
- **SSIM** — учитывает структуру, поэтому лучше отражает человеческое восприятие.
- **Эксперимент** наглядно показывает: одинаковый MSE может соответствовать совершенно разному визуальному качеству.
- **Параметры** (величина шума, доля перевёрнутых пикселей, размер окна SSIM, тип искажения) легко менять — и вы увидите, как метрики реагируют на каждое изменение.

# Разбор ноутбука `plot_pyramid.ipynb`

## 📋 Общая суть

Ноутбук показывает, **как построить пирамиду изображений** (image pyramid) — последовательность копий одной картинки, каждая из которых **уменьшена в 2 раза** по сравнению с предыдущей.

Такие пирамиды используются в:
- **шумоподавлении** (denoising),
- **анализе текстур** (texture discrimination),
- **масштабно-инвариантном поиске объектов** (scale-invariant detection),
- **поиске похожих фрагментов** на разных масштабах,
- алгоритмах типа **SIFT**, **ORB**, **Optical Flow**.

---

## 🔍 Что такое «пирамида» (немного теории)

Представьте, что вы смотрите на одну и ту же картинку с **разного расстояния**:
- **Уровень 0** — оригинал (самый детальный).
- **Уровень 1** — уменьшен в 2 раза.
- **Уровень 2** — уменьшен в 4 раза.
- **Уровень 3** — уменьшен в 8 раз.
- … и так далее, пока картинка не станет крошечной.

Перед уменьшением обычно применяют **размытие (Gaussian blur)** — чтобы избежать «муара» и артефактов. Поэтому пирамида называется **Gaussian pyramid** (`pyramid_gaussian`).

```
Уровень 0: [████████████] 512×512
Уровень 1: [██████]       256×256
Уровень 2: [███]          128×128
Уровень 3: [█]             64×64
...
```

## 🔍 Разбор по блокам

### 1️⃣ Markdown (введение)

Объясняет:
- `pyramid_gaussian` возвращает последовательность изображений.
- Каждое следующее — **уменьшено в `downscale` раз**.
- Где применяется: denoising, texture discrimination, scale-invariant detection.

### 2️⃣ Блок кода — импорты и построение пирамиды

```python
import numpy as np
import matplotlib.pyplot as plt

from skimage import data
from skimage.transform import pyramid_gaussian


image = data.astronaut()
rows, cols, dim = image.shape
pyramid = tuple(pyramid_gaussian(image, downscale=2, channel_axis=-1))
```

#### Разбор построчно:

| Строка | Что делает |
|--------|------------|
| `import numpy as np` | NumPy — для работы с массивами |
| `from skimage import data` | Тестовые изображения |
| `from skimage.transform import pyramid_gaussian` | 🎯 **Главный метод** — построение гауссовой пирамиды |
| `image = data.astronaut()` | Загрузка классического фото астронавта (512×512×3) |
| `rows, cols, dim = image.shape` | Запоминаем размеры оригинала: 512, 512, 3 |
| `pyramid_gaussian(...)` | 🎯 **Генератор**, который выдаёт уменьшенные копии |
| `downscale=2` | 🎯 Коэффициент уменьшения: каждая следующая в **2 раза меньше** |
| `channel_axis=-1` | Указывает, что последняя ось — это **каналы цвета** (RGB) |
| `tuple(...)` | Превращаем генератор в кортеж, чтобы можно было обращаться по индексу |

#### 🎯 Главный метод: `pyramid_gaussian`

- **Принимает**: изображение, `downscale` (во сколько раз уменьшать), `channel_axis`.
- **Возвращает**: **генератор**, который **лениво** выдаёт уровни пирамиды.
- **Как работает**:
  1. Размывает изображение гауссовым фильтром.
  2. Уменьшает в `downscale` раз (по умолчанию — в 2).
  3. Повторяет, пока размер не станет слишком маленьким.

#### Что получилось в `pyramid`:

```
pyramid[0]:  (512, 512, 3)   — оригинал
pyramid[1]:  (256, 256, 3)   — уменьшен в 2 раза
pyramid[2]:  (128, 128, 3)   — уменьшен в 4 раза
pyramid[3]:  ( 64,  64, 3)   — уменьшен в 8 раз
pyramid[4]:  ( 32,  32, 3)   — уменьшен в 16 раз
pyramid[5]:  ( 16,  16, 3)   — уменьшен в 32 раза
pyramid[6]:  (  8,   8, 3)   — уменьшен в 64 раза
pyramid[7]:  (  4,   4, 3)   — уменьшен в 128 раз
pyramid[8]:  (  2,   2, 3)   — уменьшен в 256 раз
pyramid[9]:  (  1,   1, 3)   — уменьшен в 512 раз
```

### 3️⃣ Markdown (комментарий)

Объясняет **идею визуализации**:
- Хотим **сложить все уровни в одну картинку**.
- Слева — оригинал.
- Справа — **вертикально столбиком** все уменьшенные копии.
- Общая ширина = `cols + pyramid[1].shape[1]` (ширина оригинала + ширина первого уменьшенного).
- Общая высота = максимум из:
  - высоты оригинала,
  - **суммы** высот всех уменьшенных копий.

**Зачем такая сложная логика с высотой?**
Потому что сумма высот уменьшенных копий может **превысить** высоту оригинала (особенно если размеры не степень двойки).

---

### 4️⃣ Блок кода — склейка всех уровней в одну картинку

```python
# determine the total number of rows and columns for the composite
composite_rows = max(rows, sum(p.shape[0] for p in pyramid[1:]))
composite_cols = cols + pyramid[1].shape[1]
composite_image = np.zeros((composite_rows, composite_cols, 3), dtype=np.double)

# store the original to the left
composite_image[:rows, :cols, :] = pyramid[0]

# stack all downsampled images in a column to the right of the original
i_row = 0
for p in pyramid[1:]:
    n_rows, n_cols = p.shape[:2]
    composite_image[i_row : i_row + n_rows, cols : cols + n_cols] = p
    i_row += n_rows

fig, ax = plt.subplots()
ax.imshow(composite_image)
plt.show()
```

#### Разбор построчно:

| Строка | Что делает |
|--------|------------|
| `composite_rows = max(rows, sum(...))` | 🎯 Высота холста = max(высота оригинала, **сумма высот** всех уменьшенных) |
| `sum(p.shape[0] for p in pyramid[1:])` | Складывает высоты всех уровней **кроме оригинала** |
| `composite_cols = cols + pyramid[1].shape[1]` | 🎯 Ширина холста = ширина оригинала + ширина **первого уменьшенного** |
| `np.zeros((composite_rows, composite_cols, 3), dtype=np.double)` | Создаём **пустой чёрный холст** нужного размера |
| `composite_image[:rows, :cols, :] = pyramid[0]` | 🎯 **Оригинал** кладём в **левый верхний угол** |
| `i_row = 0` | Счётчик строк для **правой колонки** |
| `for p in pyramid[1:]:` | Идём по всем уменьшенным уровням |
| `n_rows, n_cols = p.shape[:2]` | Берём высоту и ширину текущего уровня |
| `composite_image[i_row : i_row + n_rows, cols : cols + n_cols] = p` | 🎯 **Кладём текущий уровень** в правую колонку |
| `i_row += n_rows` | Сдвигаем счётчик вниз |
| `ax.imshow(composite_image)` | Показываем всю склейку |
| `plt.show()` | Отображаем |

## 🖼️ Что видим на выходной картинке

**Слева** — оригинальное цветное фото астронавта (512×512).

**Справа** — **вертикальный столбик** уменьшенных копий:
- **Сверху** — 256×256 (ещё можно разглядеть черты лица).
- **Ниже** — 128×128 (лицо уже «пиксельное»).
- **Ниже** — 64×64 (просто цветные пятна).
- **Ещё ниже** — 32×32, 16×16, 8×8, 4×4, 2×2, 1×1 (разноцветные квадратики, последний — один пиксель).

**Почему картинка такая «рваная»?**
- Все уровни **имеют разный размер**, а холст один.
- По мере уменьшения копии становятся всё меньше, и **вокруг них остаётся чёрная пустота**.
- Последние уровни — почти точки.

## 🛠️ Главные методы

| Метод | Что делает |
|-------|------------|
| `skimage.data.astronaut()` | Тестовое изображение астронавта |
| `skimage.transform.pyramid_gaussian()` | 🎯 **Главный метод** — генератор уровней пирамиды |
| `image.shape` | Возвращает размеры массива (высота, ширина, каналы) |
| `np.zeros(...)` | Создаёт чёрный холст |
| Срез `[:rows, :cols, :]` | Копирование фрагмента массива |
| `ax.imshow(...)` | Показ изображения |

### 🎯 Что делает `pyramid_gaussian` внутри:

1. **Гауссово размытие** текущего уровня — чтобы уменьшение не давало артефактов.
2. **Уменьшение в `downscale` раз** через прореживание (берётся каждый N-й пиксель).
3. Повтор, пока размер не станет меньше минимально допустимого (обычно 1 пиксель).

### ⚠️ Важно: это **генератор**!

```python
pyramid = pyramid_gaussian(image)   # не список, а генератор!
next(pyramid)  # получить первый уровень (оригинал)
next(pyramid)  # получить второй уровень (уменьшенный)
...
```

Но в ноутбуке его **сразу превращают в кортеж** через `tuple(...)`, чтобы:
- можно было обращаться по индексу (`pyramid[0]`, `pyramid[1]`, ...),
- использовать `len(pyramid)`,
- перебирать несколько раз.

## 🎛️ Что можно менять и что будет

# Разбор ноутбука `plot_rgb_to_hsv.ipynb`

## 📋 Общая суть

Ноутбук показывает, **как перевести изображение из RGB в HSV** и использовать это для **сегментации** (выделения объектов). Главная идея: в RGB цвет «размазан» по трём каналам, а в HSV — **оттенок (Hue)**, **насыщенность (Saturation)** и **яркость (Value)** лежат в отдельных каналах. Значит, объект можно выделить **простым порогом** по нужному каналу.

---

## 🎨 Что такое HSV (немного теории)

| Канал | Что означает | Диапазон |
|-------|-------------|----------|
| **H (Hue)** — Оттенок | «Какой это цвет»: красный, жёлтый, зелёный... | 0…1 (0°…360°) |
| **S (Saturation)** — Насыщенность | «Насколько цвет чистый» (0 — серый, 1 — яркий) | 0…1 |
| **V (Value)** — Яркость | «Насколько светло» | 0…1 |

**Почему это удобно?**
В RGB, чтобы выделить «коричневую чашку», пришлось бы ставить условия сразу по трём каналам (`R>100 и G<80 и B<50`). В HSV достаточно одного условия: `Hue в диапазоне коричневого`. Это гораздо проще и надёжнее.

---

### 1️⃣ Markdown (введение)
Объясняет, что HSV удобен для сегментации: цвет и яркость **разделены**, поэтому объекты легко отделяются порогом.

**Панель 2 — Hue channel:** выглядит как **радужный ребус**:
- Фон стола — **красно-оранжевый** (у стола оттенок ближе к красному).
- Чашка — **жёлто-зелёный** (у неё другой оттенок).

- Value-канал показывает **светлоту**, но не оттенок.

hue_threshold = 0.04

| `hue_img > hue_threshold` | 🎯 **Бинарная маска**: где Hue > 0.04 → `True`, где меньше → `False` |
| `hue_img.ravel()` | Превращает 2D-массив в одномерный — чтобы построить гистограмму |
| `ax0.hist(..., 512)` | Гистограмма распределения значений Hue (512 «корзин») |

**Левая — гистограмма Hue:**
- Большой пик справа от порога — это **чашка** (её оттенок).
- Маленькие значения слева от порога — **фон** (у стола оттенок ближе к 0).

**Правая — бинарное изображение:**
- **Белое** — где Hue > 0.04 (чашка).
- **Чёрное** — фон и тени.

**Что получилось?** Чашка выделена, но с «мусором»: в тень упали частицы, которые тоже попали под порог.

### 7️⃣ Markdown: «We finally perform an additional thresholding on the Value channel...»
Комментарий: **дополнительно поставим порог на Value**, чтобы убрать тени.

### 8️⃣ Блок кода — комбинированный порог

```python
fig, ax0 = plt.subplots(figsize=(4, 3))

value_threshold = 0.10
binary_img = (hue_img > hue_threshold) | (value_img < value_threshold)

ax0.imshow(binary_img)
ax0.set_title("Hue and value thresholded image")
ax0.axis('off')

fig.tight_layout()
plt.show()
```

#### Разбор построчно:

| Строка | Что делает |
|--------|------------|
| `value_threshold = 0.10` | 🎯 Порог по **яркости** |
| `(hue_img > hue_threshold) \| (value_img < value_threshold)` | 🎯 **Логическое ИЛИ**: «Hue больше 0.04» **ИЛИ** «Value меньше 0.1» |
| `ax0.imshow(binary_img)` | Показывает финальную маску |

#### 🖼️ Что видим (третья картинка):

- **Белое** — это либо чашка (по Hue), либо очень тёмные места (по Value).
- **Тени чашки** стали **чёрными** (потому что они тёмные по Value, но не попадают под Hue).
- Результат: **чище отделена чашка от фона**.

**Как это работает?**
В тенях Hue может «съезжать» (например, коричневый становится почти чёрным, и его оттенок уже не в диапазоне чашки). Порог по Value «отсекает» эти тёмные области — но в нашем случае поставили `value_img < value_threshold`, то есть **тёмные области становятся частью маски** — тем самым «приклеиваем» тени к чашке.

> 📌 **Хитрость**: логика `(hue > th) | (value < th)` — это union (объединение), а не intersection (пересечение). Смысл: «чашка + тёмные тени вокруг неё». Если бы мы хотели **убрать** тени, поставили бы `& (value_img > value_threshold)`.

# Разбор ноутбука `plot_rgb_to_gray.ipynb`

## 📋 Общая суть

Ноутбук демонстрирует **преобразование цветного изображения (RGB) в оттенки серого (grayscale)** с помощью библиотеки `scikit-image`. Это классический пример из области обработки изображений.

---

## 🔍 Разбор по блокам

### 1️⃣ Markdown-блок (теория)

Здесь объясняется формула перевода цвета в серый:

```
Y = 0.2125·R + 0.7154·G + 0.0721·B
```

**Что это значит:**
- Каждый серый пиксель — это **взвешенная сумма** красного, зелёного и синего каналов.
- Веса **не равны** (не 1/3 каждому!), потому что человеческий глаз **по-разному воспринимает** цвета:
  - 🟢 Зелёный — самый «яркий» для нас (вес 0.7154)
  - 🔴 Красный — средний (0.2125)
  - 🔵 Синий — самый «тусклый» (0.0721)

Эти коэффициенты называются **коэффициентами яркости (luminance)** и используются в CRT-мониторах, стандарте NTSC и т.д.

ax[0].set_title("Original")

## 🎨 Главные методы

### `skimage.data.astronaut()`
- Возвращает **тестовое изображение** астронавта Эйлин Коллинз.
- Формат: NumPy-массив размером `(512, 512, 3)`.
- Значения пикселей: `uint8` (0–255) или `float` (0–1).
- Используется почти во всех примерах scikit-image — удобный «эталон».

### `skimage.color.rgb2gray(image)`
- **Главный метод ноутбука.**
- Принимает RGB-массив, возвращает **двумерный массив** (высота × ширина) — один канал вместо трёх.
- Работает по формуле: `Y = 0.2125·R + 0.7154·G + 0.0721·B`.
- Возвращает `float` в диапазоне `[0, 1]`.

### `matplotlib.pyplot.imshow()`
- Отображает массив как картинку.
- `cmap` — цветовая карта. Для 1-канальных данных без `cmap='gray'` картинка будет выглядеть странно (сине-красной).

---

## 🖼️ Что мы видим на выходе

**Слева** — оригинальное цветное фото астронавта: красный скафандр, синий фон, телесные тона.

**Справа** — то же фото в оттенках серого:
- Красный скафандр стал **средне-серым** (потому что R имеет вес 0.21).
- Зелёные/жёлтые детали — **светлее** (вес 0.71).
- Синий фон — **очень тёмный** (вес всего 0.07).

**Почему так?**
Если бы мы просто усреднили `(R+G+B)/3`, то синий фон был бы таким же светлым, как и зелёный. А так — серый тон **соответствует реальной воспринимаемой яркости** для человеческого глаза.

### Ноутбук 1: `plot_active_contours.ipynb` (Активные контуры)

#### 1. В чем основная суть?

Этот ноутбук демонстрирует **метод активных контуров** (также известный как "змеи" или *snakes*). Представьте, что у вас есть изображение, и вы хотите автоматически обвести на нем какой-то объект (например, лицо человека или букву). Метод активных контуров работает так:

1.  Вы вручную задаете начальную кривую (например, круг вокруг лица).
2.  Алгоритм начинает "двигать" эту кривую, как будто она живая.
3.  Кривая стремится к краям объекта на изображении, одновременно стараясь оставаться гладкой и не растягиваться слишком сильно.

Это достигается за счет минимизации "энергии". Энергия состоит из двух частей:
*   **Внутренняя энергия:** штрафует кривую за то, что она слишком длинная или изломанная. Заставляет ее быть гладкой.
*   **Внешняя энергия:** зависит от изображения. Кривая "притягивается" к краям (местам с сильным перепадом яркости) или к темным/светлым областям.

#### 2. Главные методы и библиотеки:

*   `skimage.segmentation.active_contour(...)`: **Это главная функция.** Она принимает на вход изображение и начальный контур, а возвращает новый, "подстроившийся" контур.
*   `skimage.filters.gaussian(...)`: Используется для предварительного размытия изображения. Это важно, чтобы убрать шум и сделать края более четкими для алгоритма.
*   `np.linspace(...)` и `np.array(...).T`: Используются для создания начального контура. В первом примере это круг, во втором — прямая линия.
*   `matplotlib.pyplot`: Для отображения исходного изображения, начального контура (красный пунктир) и конечного результата (синяя линия).

#### 3. Что мы наблюдаем на картинках и как это объясняется?

**Пример 1: Обводка лица космонавта**

*   **Что видим:** На первом графике мы видим фотографию космонавта. Вокруг его лица нарисован красный пунктирный круг — это начальный контур. Синяя сплошная линия — это результат работы алгоритма. Она плотно обвела контур лица.
*   **Как это объясняется:** Алгоритм взял начальный круг и начал его "сплющивать" и изгибать, чтобы синяя линия легла на границы лица (волосы, подбородок, щеки). Параметр `w_edge=1` (по умолчанию) заставляет контур искать края. Параметр `alpha=0.015` отвечает за гладкость (чтобы линия не была угловатой), а `beta=10` — за жесткость (чтобы она не сильно растягивалась).

**Пример 2: Поиск темной линии на изображении с текстом**

*   **Что видим:** На втором графике изображен текст. Красная пунктирная линия — это начальная прямая, проведенная между двумя точками. Синяя линия — это результат. Она изогнулась и "прилипла" к одной из темных букв.
*   **Как это объясняется:** Здесь мы изменили параметры. `boundary_condition='fixed'` означает, что концы нашей линии зафиксированы в начальных точках (5, 136) и (424, 50). Параметр `w_line=-5` заставляет контур искать **темные** линии (отрицательный вес), а `w_edge=0` отключает поиск краев. Поэтому синяя линия "поползла" вниз, чтобы найти самую темную область на своем пути, при этом оставаясь гладкой.

#### 4. Можно ли менять параметры и к чему это приведет?

Да, это самый интересный момент! Вот основные параметры `active_contour`:

*   **`alpha` (α):** Отвечает за **гладкость** контура.
    *   **Увеличить:** Контур станет более жестким, менее гибким. Он будет игнорировать мелкие детали и стремиться к более простой форме.
    *   **Уменьшить:** Контур станет более гибким, сможет огибать мелкие детали, но может стать "изломанным" или поймать шум.
*   **`beta` (β):** Отвечает за **жесткость** или сопротивление растяжению.
    *   **Увеличить:** Контур будет сложнее растянуть или сжать. Он будет стремиться сохранить свою длину.
    *   **Уменьшить:** Контур сможет легко растягиваться и сжиматься, чтобы принять нужную форму.
*   **`gamma` (γ):** Это **шаг** обучения. Он определяет, насколько сильно контур смещается на каждой итерации.
    *   **Увеличить:** Контур будет двигаться быстрее, но может "проскочить" нужный край или вести себя нестабильно.
    *   **Уменьшить:** Движение будет медленным и более точным.
*   **`w_line`:** Вес для притяжения к **линиям** (ярким или темным).
    *   **Положительный:** Контур притягивается к ярким линиям.
    *   **Отрицательный:** Контур притягивается к темным линиям.
    *   **Ноль:** Притяжение к линиям отключается.
*   **`w_edge`:** Вес для притяжения к **краям** (границам объектов).
    *   **Положительный:** Контур притягивается к краям. Это стандартное поведение для сегментации.
    *   **Ноль:** Контур перестает искать края и полагается только на `w_line` и внутреннюю энергию.
*   **`boundary_condition`:** Условие на границах контура.
    *   `'periodic'`: Контур замкнут (как в первом примере с кругом).
    *   `'fixed'`: Концы контура зафиксированы (как во втором примере с линией).
    *   `'free'`: Концы контура могут свободно двигаться.

Меняя эти параметры, можно настраивать алгоритм под разные задачи: обводить объекты с разной степенью детализации, искать линии определенной яркости и т.д.

### Ноутбук 2: `plot_adapt_rgb.ipynb` (Адаптация фильтров для RGB)

#### 1. В чем основная суть?

Многие классические фильтры для обработки изображений (например, фильтр Собеля для выделения границ) были придуманы для **черно-белых** изображений. Они работают с одним значением яркости для каждого пикселя.

Но что делать, если у нас **цветное** изображение (RGB)? Применять фильтр к каждому цветовому каналу по отдельности? Или преобразовать изображение в другой цветовой формат? Этот ноутбук показывает, как с помощью декоратора `adapt_rgb` можно легко "адаптировать" черно-белые фильтры для работы с цветными изображениями двумя разными способами.

#### 2. Главные методы и библиотеки:

*   `skimage.color.adapt_rgb`: **Это ключевой инструмент.** Это декоратор, который "оборачивает" вашу функцию-фильтр и заставляет ее работать с цветными изображениями.
*   `each_channel` и `hsv_value`: Это две **стратегии** адаптации.
    *   `each_channel`: Применяет фильтр к каждому каналу (R, G, B) по отдельности, а потом объединяет результаты обратно в цветное изображение.
    *   `hsv_value`: Преобразует изображение в формат HSV (Hue, Saturation, Value — Цветовой тон, Насыщенность, Значение/Яркость), применяет фильтр только к каналу **Value (Яркость)**, а потом преобразует обратно в RGB.
*   `skimage.filters.sobel(...)`: Пример черно-белого фильтра, который выделяет границы. Мы будем его адаптировать.
*   `skimage.exposure.rescale_intensity(...)`: Используется для нормализации результата, чтобы его было лучше видно (инвертирует и растягивает диапазон яркости).

#### 3. Что мы наблюдаем на картинках и как это объясняется?

*   **Что видим:** Мы видим два изображения космонавта, обработанных фильтром Собеля двумя разными способами.
    *   **Слева (`Sobel on individual RGB channels`):** Границы выглядят цветными. Например, граница между красным и синим будет выделена и в красном, и в синем канале.
    *   **Справа (`Sobel on (V)alue converted image (HSV)`):** Границы выглядят более однородными, сероватыми. Они выделяют контуры объектов, но не так сильно реагируют на изменение цвета.

*   **Как это объясняется:**
    *   **`each_channel`:** Поскольку фильтр применяется к каждому цветовому каналу отдельно, границы, которые видны только в одном канале (например, переход от красного к зеленому), будут выделены только в этом канале. В результате, когда мы объединяем каналы, границы получаются разноцветными.
    *   **`hsv_value`:** Этот метод сначала "отбрасывает" информацию о цвете, оставляя только яркость (канал Value). Фильтр Собеля ищет границы на этой "черно-белой" версии. Поэтому он находит контуры, основанные на изменении яркости, а не цвета. Результат выглядит более чистым и монохромным.

#### 4. Можно ли менять параметры и к чему это приведет?

В этом ноутбуке основной "параметр" — это **выбор стратегии адаптации**.

*   **Можно попробовать другие фильтры:** Вместо `filters.sobel` можно использовать любой другой черно-белый фильтр, например, `filters.roberts`, `filters.prewitt` или даже `filters.gaussian`. Результат будет зависеть от свойств самого фильтра.
*   **Можно комбинировать стратегии:** Например, можно применить один фильтр через `each_channel`, а другой — через `hsv_value`.
*   **Можно написать свою стратегию:** `adapt_rgb` позволяет передать любую функцию, которая будет решать, как адаптировать изображение. Например, можно преобразовать изображение в формат LAB и применить фильтр только к каналу L (яркость).

**Что будет меняться:**
*   **Выбор фильтра:** Разные фильтры по-разному реагируют на границы (например, фильтр Робертса более чувствителен к диагональным границам).
*   **Выбор стратегии:** `each_channel` хорош для выделения цветовых границ, а `hsv_value` — для выделения контуров объектов, игнорируя цвет.

**Итог:** Этот ноутбук — отличный пример того, как можно легко и гибко адаптировать старые, проверенные алгоритмы для работы с современными цветными изображениями, не переписывая их с нуля.
Отлично, разберем оставшиеся четыре ноутбука в том же простом и понятном стиле.

### Ноутбук 3: `plot_piecewise_affine.ipynb` (Кусочно-аффинное преобразование)

#### 1. В чем основная суть?

Этот ноутбук демонстрирует **кусочно-аффинное преобразование**. Это способ деформировать изображение, но не целиком (как при повороте или растяжении), а **по частям**. Изображение как бы разбивается на множество маленьких треугольников, и каждый треугольник деформируется по-своему.

Метод работает так:
1.  На исходном изображении задается сетка из точек (узлов).
2.  Для каждого узла указывается его новое положение (куда он должен переместиться).
3.  Алгоритм строит преобразование, которое плавно "перетаскивает" все пиксели изображения из старых положений в новые, интерполируя значения между узлами.

Это похоже на то, как если бы вы взяли фотографию, наложили на нее эластичную сетку и начали тянуть за узлы этой сетки.

#### 2. Главные методы и библиотеки:

*   `skimage.transform.PiecewiseAffineTransform`: **Это ключевой класс.** Он создает объект преобразования на основе соответствия между исходными и целевыми точками.
*   `PiecewiseAffineTransform.from_estimate(src, dst)`: **Главный метод.** Он берет два набора точек (`src` — исходные, `dst` — целевые) и вычисляет преобразование, которое наилучшим образом их сопоставляет.
*   `skimage.transform.warp(image, tform, ...)`: **Функция для применения преобразования.** Она берет изображение и объект преобразования `tform` и выдает новое, деформированное изображение.
*   `np.meshgrid(...)` и `np.dstack(...)`: Используются для создания регулярной сетки исходных точек.
*   `np.sin(...)`: Используется для создания синусоидальной деформации (волнообразного искажения).

#### 3. Что мы наблюдаем на картинке и как это объясняется?

*   **Что видим:** На графике мы видим изображение космонавта, которое сильно искажено. Оно как будто "растянуто" по вертикали и имеет волнообразные искажения. Поверх изображения нанесены синие точки.
*   **Как это объясняется:**
    *   **Волнообразное искажение:** В коде создается сетка точек, а затем к их вертикальным координатам (`dst_rows`) добавляется синусоидальная функция. Это заставляет разные части изображения смещаться вверх и вниз по-разному, создавая эффект волны.
    *   **Растяжение:** Строка `dst_rows *= 1.5` умножает вертикальные координаты на 1.5, что растягивает изображение по вертикали.
    *   **Синие точки:** `ax.plot(tform.inverse(src)[:, 0], ...)` — это отображение **обратного преобразования**. Мы берем исходные точки `src` и смотрим, куда они "попали" бы в новом изображении. Эти точки показывают, как деформировалась сетка.

#### 4. Можно ли менять параметры и к чему это приведет?

Да, здесь много возможностей для экспериментов:

*   **`20` и `10` в `np.linspace`:** Это **плотность сетки**.
    *   **Увеличить:** Сетка станет плотнее (больше узлов). Деформация будет более плавной и точной, но вычисления займут больше времени.
    *   **Уменьшить:** Сетка станет грубее. Деформация будет более "угловатой" и резкой.
*   **`np.sin(...) * 50`:** Это **амплитуда волны**.
    *   **Увеличить `50`:** Волны станут более выраженными (сильнее искажение).
    *   **Уменьшить `50`:** Волны станут почти незаметными.
*   **`3 * np.pi`:** Это **частота волны**.
    *   **Увеличить:** Волн станет больше (они будут "мельче").
    *   **Уменьшить:** Волн станет меньше (одна большая волна).
*   **`dst_rows *= 1.5`:** Это **коэффициент растяжения по вертикали**.
    *   **Изменить на 2.0:** Изображение растянется еще сильнее.
    *   **Изменить на 1.0:** Растяжение исчезнет.
*   **Самое интересное:** Можно **вручную задать** новые координаты для нескольких узлов, чтобы создать, например, эффект "улыбки" на лице или искажения отдельных частей тела.

### Ноутбук 4: `plot_pyramid.ipynb` (Построение пирамид изображений)

#### 1. В чем основная суть?

Этот ноутбук показывает, как построить **пирамиду изображений**. Это набор изображений, где каждое следующее является уменьшенной (и размытой) версией предыдущего.

Зачем это нужно?
*   **Поиск объектов разного масштаба:** Если вы ищете лицо на фото, оно может быть большим или маленьким. Пирамида позволяет искать его на разных уровнях.
*   **Ускорение вычислений:** Обработка маленького изображения происходит быстрее, чем большого.
*   **Удаление шума:** Размытие и уменьшение помогают избавиться от мелкого шума.

#### 2. Главные методы и библиотеки:

*   `skimage.transform.pyramid_gaussian(image, downscale=2, ...)`: **Главная функция.** Это **генератор**, который выдает последовательность изображений. Каждое следующее изображение в `downscale` раз меньше предыдущего (в данном случае в 2 раза).
*   `tuple(...)`: Превращает генератор в кортеж, чтобы можно было получить доступ ко всем изображениям сразу (например, `pyramid[0]`, `pyramid[1]`).
*   `channel_axis=-1`: Указывает, что последняя ось изображения — это цветовые каналы (RGB).
*   `np.zeros(...)`: Создает пустое (черное) изображение для "холста", на котором мы будем собирать композитную картинку.

#### 3. Что мы наблюдаем на картинке и как это объясняется?

*   **Что видим:** Мы видим одно большое изображение, которое состоит из:
    *   **Слева:** Оригинальное изображение космонавта.
    *   **Справа:** Столбик из уменьшенных копий. Самая верхняя копия — это оригинал, уменьшенный в 2 раза. Следующая — в 4 раза, и так далее, пока изображение не станет совсем крошечным.
*   **Как это объясняется:** Код создает пустой "холст" и последовательно "вставляет" в него все изображения из пирамиды. Оригинал ставится слева, а все уменьшенные версии — друг под другом справа.

#### 4. Можно ли менять параметры и к чему это приведет?

*   **`downscale`:** Это **коэффициент уменьшения**.
    *   **`downscale=2`:** Каждое следующее изображение в 2 раза меньше. Это классический вариант.
    *   **`downscale=1.5`:** Изображения будут уменьшаться медленнее, и пирамида будет содержать больше уровней.
    *   **`downscale=4`:** Изображения будут уменьшаться быстрее, и пирамида будет короче.
*   **`pyramid_gaussian` vs `pyramid_laplacian`:** В `skimage` есть также `pyramid_laplacian`. **Лапласианская пирамида** хранит не уменьшенные изображения, а **разницу** между уровнями. Она используется для сжатия изображений (например, в формате JPEG2000) и для анализа текстур.
*   **`max_layer`:** Можно ограничить количество уровней в пирамиде.
*   **Предварительное размытие:** Можно добавить `gaussian(image, sigma=...)` перед построением пирамиды, чтобы сильнее подавить шум.

### Ноутбук 5: `plot_ssim.ipynb` (Индекс структурного сходства)

#### 1. В чем основная суть?

Этот ноутбук сравнивает два способа оценки качества изображения: **MSE** (Mean Squared Error — среднеквадратичная ошибка) и **SSIM** (Structural Similarity Index — индекс структурного сходства).

*   **MSE:** Просто считает среднюю разницу в яркости между пикселями двух изображений. Чем меньше, тем лучше. Но у него есть проблема: он не учитывает, как мы, люди, воспринимаем изображение.
*   **SSIM:** Более "умная" метрика. Она сравнивает не только яркость, но и **структуру, контраст и текстуру**. SSIM пытается предсказать, насколько похожими изображения покажутся человеческому глазу. Значение SSIM от 0 до 1, где 1 — полное сходство.

Ноутбук показывает, что MSE может вводить в заблуждение: два изображения могут иметь одинаковую MSE, но выглядеть совершенно по-разному.

#### 2. Главные методы и библиотеки:

*   `skimage.metrics.structural_similarity(...)`: **Главная функция для SSIM.**
*   `skimage.metrics.mean_squared_error(...)`: **Главная функция для MSE.**
*   `skimage.img_as_float(...)`: Преобразует изображение в числа с плавающей точкой от 0 до 1, что удобно для вычислений.
*   `data_range`: Важный параметр для SSIM. Он указывает диапазон яркости изображения (например, `max - min`), чтобы метрика работала корректно.

#### 3. Что мы наблюдаем на картинках и как это объясняется?

*   **Что видим:** Три изображения:
    1.  **Original image:** Оригинал.
    2.  **Image with noise:** Изображение с шумом (случайные черные и белые точки).
    3.  **Image plus constant:** Изображение, к которому прибавили константу (сделали его ярче).
*   **Подписи:** Под каждым изображением указаны значения MSE и SSIM.
*   **Ключевое наблюдение:**
    *   **MSE для шума и для константы может быть одинаковым!** Это потому, что в обоих случаях средняя разница в яркости пикселей одинакова.
    *   **SSIM для шума будет низким, а для константы — высоким.**
*   **Как это объясняется:** Наш глаз воспринимает шум как сильное искажение, потому что он разрушает структуру и текстуру. А простое повышение яркости (константа) почти не меняет структуру — мы легко узнаем изображение. SSIM это улавливает, а MSE — нет.

#### 4. Можно ли менять параметры и к чему это приведет?

*   **`0.2` в `noise = ... * 0.2 * ...`:** Это **амплитуда шума**.
    *   **Увеличить:** Шум станет сильнее, SSIM упадет, MSE вырастет.
    *   **Уменьшить:** Шум станет слабее, SSIM будет ближе к 1.
*   **`0.5` в `rng.random(size=noise.shape) > 0.5`:** Это **плотность шума**.
    *   **Увеличить:** Больше пикселей будет затронуто шумом.
    *   **Уменьшить:** Меньше пикселей будет затронуто.
*   **Вместо `abs(noise)` можно попробовать другие искажения:**
    *   **Размытие:** `img_blur = gaussian(img, sigma=2)`. MSE будет небольшим, а SSIM может сильно упасть, потому что размытие разрушает текстуру.
    *   **Сжатие JPEG:** Можно сохранить изображение в JPEG с низким качеством и загрузить обратно. SSIM хорошо показывает артефакты сжатия.
*   **`data_range`:** Если неправильно указать этот параметр, значения SSIM будут неверными. Он должен соответствовать реальному диапазону яркости изображения.

### Ноутбук 6: `plot_swirl.ipynb` (Вихрь)

#### 1. В чем основная суть?

Этот ноутбук демонстрирует **нелинейное искажение изображения**, которое создает эффект **водоворота или вихря**. Изображение как бы закручивается вокруг определенной точки.

В основе лежит **обратное преобразование**. Вместо того чтобы для каждого пикселя исходного изображения искать его новое место, мы для каждого пикселя **нового** изображения ищем, откуда он "пришел" на исходном. Это позволяет избежать пустых мест в результате.

#### 2. Главные методы и библиотеки:

*   `skimage.transform.swirl(image, rotation=..., strength=..., radius=...)`: **Главная функция.** Она делает все "под капотом".
*   `skimage.transform.warp(image, ...)`: Функция, которая выполняет само искажение, но в этом ноутбуке она используется косвенно, через `swirl`.
*   **Математика:** В Markdown-ячейке подробно описана математика преобразования. Для каждой точки нового изображения вычисляются полярные координаты `(ρ, θ)`, а затем угол `θ` изменяется на величину, которая зависит от расстояния до центра `ρ`. Чем ближе к центру, тем сильнее закручивание. Экспоненциальная функция `e^{-ρ / r}` обеспечивает плавное затухание эффекта к краям.

#### 3. Что мы наблюдаем на картинке и как это объясняется?

*   **Что видим:** Слева — оригинальное изображение шахматной доски. Справа — то же изображение, но в центре оно закручено в спираль.
*   **Как это объясняется:** Алгоритм берет каждую точку на новом изображении, определяет ее расстояние до центра и угол. Затем он изменяет угол на величину, которая тем больше, чем ближе точка к центру. После этого он "спрашивает" у исходного изображения: "А какой пиксель находится по этим новым координатам?" и берет его значение. В результате линии шахматной доски искривляются, закручиваясь вокруг центра.

#### 4. Можно ли менять параметры и к чему это приведет?

Да, у функции `swirl` есть три основных параметра:

*   **`strength` (сила):** Насколько сильно закручивать изображение.
    *   **Увеличить (например, до 20):** Изображение закрутится в несколько оборотов, как в центре урагана.
    *   **Уменьшить (например, до 2):** Эффект будет едва заметным.
    *   **`strength=0`:** Никакого эффекта.
*   **`radius` (радиус):** Радиус области, в которой происходит закручивание.
    *   **Увеличить:** Закручивание захватит большую часть изображения.
    *   **Уменьшить:** Закрутится только маленькая область в центре.
*   **`rotation` (вращение):** Добавляет постоянный угол поворота ко всему изображению.
    *   **`rotation=1.5`:** В дополнение к закручиванию, все изображение немного повернется.
    *   **`rotation=0`:** Только закручивание, без общего поворота.
*   **`center` (центр):** Координаты центра вихря.
    *   По умолчанию — центр изображения. Можно переместить вихрь в любой угол.

Меняя эти параметры, можно создавать самые разные визуальные эффекты: от легкого искажения до сильного закручивания целых областей.
