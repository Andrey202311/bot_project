# Построение грамматики подмножества языка Рапира

Ниже — раздел «Построение грамматики», выполненный по той же схеме, что и в примере из методических материалов (множество терминалов → первое правило «структура программы» → правила-списки с рекурсией → нетерминалы для необязательных частей → итоговая G → проверка выводом), но **только для конструкций из примера программы задания**.

---

## 1. Разбор фрагмента программы на части

```
ИМЕНА x, d;                ← описательная часть (директива объявления имён)
3 -> m;                    ← операторная часть
ВЫБОР m ИЗ                 ← операторная часть (оператор выбора)
2 : 7*4 -> d;
4, 6, 9, 11 : 30 -> d;
ИНАЧЕ 31 -> d;
ВСЕ;
КНЦ;                       ← признак конца программы
```

**Описательная часть** — директива объявления имени `ИМЕНА` со списком имён через запятую, завершается `;`.

**Операторная часть** — последовательность операторов двух видов:
- **оператор присваивания**: в Рапире значение «отправляется стрелкой» в переменную — `<выражение> -> <имя>;` (пример: `3 -> m;`, `7*4 -> d;`);
- **оператор выбора**: `ВЫБОР <имя> ИЗ <варианты> [ИНАЧЕ <оператор>] ВСЕ;`, где вариант — это `список констант : оператор;`; ветвь `ИНАЧЕ` может отсутствовать.

**`КНЦ;`** — признак конца программы (аналог `end.` в Паскале из примера).

Соответствие элементам задания (п. 7.6):

| Элемент задания | Где в грамматике |
|---|---|
| идентификаторы (рус/лат, ≤6 симв., регистронезависимые) | терминал `id` (уровень сканера) |
| 1-байтовые целые константы | терминал `lit` (уровень сканера) |
| директива объявления имени | правила 2–4 |
| сложный арифметический оператор с `**` | правила 7, 13–16 |
| оператор выбора `ВЫБОР…ИЗ…[ИНАЧЕ]…ВСЕ` | правила 8–12 |

## 2. Множество терминальных символов

**T** = { ИМЕНА, ВЫБОР, ИЗ, ИНАЧЕ, ВСЕ, КНЦ, **->**, **, +, −, *, /, (, ), :, ;, «,», id, lit }

- служебные слова: `ИМЕНА`, `ВЫБОР`, `ИЗ`, `ИНАЧЕ`, `ВСЕ`, `КНЦ`;
- знаки операций: `->`, `**`, `+`, `−`, `*`, `/`;
- разделители: `( ) : ; ,`;
- классы лексем (порождаются сканером): `id`, `lit`.

*Примечание:* ограничения «длина ≤ 6», «константа в диапазоне 0..255», регистронезависимость — это проверки **лексического** уровня, в грамматику `id` и `lit` входят как обычные терминалы. Двухлитерный разделитель `**` сканер обязан распознавать как одну лексему (принцип максимального поглощения).

## 3. Построение правил

**Правило 1 — общая структура программы** (первое правило, как в примере): описательная часть, затем операторная, завершается `КНЦ;`. Слово `ИМЕНА` ограничивает начало описательной части, `КНЦ` — конец операторной (аналог `var` и `end.` в Паскале):

```
(1)  <программа> ::= <спис_опис> <спис_опер> КНЦ ;
```

**Описательная часть.** Директива одна, но оформляем её как рекурсивный список (методика: правила-списки «размножают» элемент в количестве один и более):

```
(2)  <спис_опис>   ::= <опис> | <спис_опис> <опис>
(3)  <опис>        ::= ИМЕНА <спис_имен> ;
(4)  <спис_имен>   ::= id | <спис_имен> , id
```

**Операторная часть.** Каждый оператор завершается `;`, поэтому `;` включаем в определение оператора:

```
(5)  <спис_опер>   ::= <опер> | <спис_опер> <опер>
(6)  <опер>        ::= <присв> ; | <выбор> ;
```

**Оператор присваивания.** Слева вычисляется выражение, справа — имя переменной:

```
(7)  <присв> ::= <выраж> -> id
```

**Оператор выбора.** Часть `ИНАЧЕ …` может отсутствовать — по методике вводим для неё отдельный нетерминал с пустой альтернативой ε (как `<альт.>` для `else` в примере):

```
(8)   <выбор>          ::= ВЫБОР id ИЗ <спис_вариантов> <альт> ВСЕ
(9)   <спис_вариантов> ::= <вариант> | <спис_вариантов> <вариант>
(10)  <вариант>        ::= <спис_констант> : <опер>
(11)  <спис_констант> ::= lit | <спис_констант> , lit
(12)  <альт>           ::= ИНАЧЕ <опер> | ε
```

**Арифметические выражения** (сюда попадает операция `**`). Приоритеты задаются вложенностью нетерминалов: `**` выше `* /`, те выше `+ −`; `**` правоассоциативна (правило 15 рекурсивно справа):

```
(13)  <выраж> ::= <слаг> | <выраж> + <слаг> | <выраж> − <слаг>
(14)  <слаг>  ::= <степ> | <слаг> * <степ> | <слаг> / <степ>
(15)  <степ>  ::= <элем> | <элем> ** <степ>
(16)  <элем>  ::= id | lit | ( <выраж> )
```

## 4. Итоговая грамматика

**G = ⟨ T, N, P, ⟨программа⟩ ⟩**

- **T** = {ИМЕНА, ВЫБОР, ИЗ, ИНАЧЕ, ВСЕ, КНЦ, ->, **, +, −, *, /, (, ), :, ;, «,», id, lit}
- **N** = {⟨программа⟩, ⟨спис_опис⟩, ⟨опис⟩, ⟨спис_имен⟩, ⟨спис_опер⟩, ⟨опер⟩, ⟨присв⟩, ⟨выбор⟩, ⟨спис_вариантов⟩, ⟨вариант⟩, ⟨спис_констант⟩, ⟨альт⟩, ⟨выраж⟩, ⟨слаг⟩, ⟨степ⟩, ⟨элем⟩}
- **P** — правила (1)–(16), выписанные выше.

Все правила имеют вид A → β, где A ∈ N, т.е. **G — контекстно-свободная грамматика (тип 2 по Хомскому)**, записанная в форме Бэкуса–Наура.

Важно для вашего задания: разбор по условию курсовой — **LR(k)**, поэтому левая рекурсия в правилах списков (2, 4, 5, 9, 11) и выражений (13, 14) **сохранена намеренно** — для восходящего разбора она допустима и естественна, устранять её (как в LL-методе) не требуется. Грамматика пригодна для LR(1)-разбора: конфликтов сдвиг–свёртка не возникает (например, выбор между `<альт> → ИНАЧЕ <опер>` и `<альт> → ε` однозначно определяется текущим символом: `ИНАЧЕ` либо `ВСЕ`).

*Если* разбор выражений решено вынести в отдельный модуль (как `<expr>` в примере на лекции), правила (13)–(16) убираются, а (7) заменяется на `<присв> ::= expr -> id`.

## 5. Проверка грамматики (контрольный вывод)

Имитируем работу нисходящего анализатора — строим левый вывод фрагмента (многоточием обозначена неизменяемая часть цепочки, в скобках — номер применённого правила):

```
<программа>
 ⇒ <спис_опис> <спис_опер> КНЦ ;                                          (1)
 ⇒ <опис> <спис_опер> КНЦ ;                                               (2)
 ⇒ ИМЕНА <спис_имен> ; <спис_опер> КНЦ ;                                  (3)
 ⇒ ИМЕНА <спис_имен> , id ; <спис_опер> КНЦ ;                             (4)
 ⇒ ИМЕНА id , id ; <спис_опер> КНЦ ;                                      (4)
 ⇒ ИМЕНА id , id ; <спис_опер> <опер> КНЦ ;                               (5)
 ⇒ ИМЕНА id , id ; <опер> <опер> КНЦ ;                                    (5)
 ⇒ ИМЕНА id , id ; <присв> ; <опер> КНЦ ;                                (6)
 ⇒ ИМЕНА id , id ; <выраж> -> id ; <опер> КНЦ ;                           (7)
 ⇒ ИМЕНА id , id ; <слаг> -> id ; …                                       (13)
 ⇒ ИМЕНА id , id ; <степ> -> id ; …                                       (14)
 ⇒ ИМЕНА id , id ; <элем> -> id ; …                                       (15)
 ⇒ ИМЕНА id , id ; lit -> id ; <опер> КНЦ ;                               (16)
 ⇒ ИМЕНА id , id ; lit -> id ; <выбор> ; КНЦ ;                            (6)
 ⇒ … ВЫБОР id ИЗ <спис_вариантов> <альт> ВСЕ ; КНЦ ;                      (8)
 ⇒ … ВЫБОР id ИЗ <спис_вариантов> <вариант> <альт> ВСЕ ; КНЦ ;            (9)
 ⇒ … ВЫБОР id ИЗ <вариант> <вариант> <альт> ВСЕ ; КНЦ ;                    (9)
 ⇒ … ВЫБОР id ИЗ <спис_констант> : <опер> <вариант> <альт> ВСЕ ; КНЦ ;    (10)
 ⇒ … ВЫБОР id ИЗ lit : <опер> <вариант> <альт> ВСЕ ; КНЦ ;                (11)
 ⇒ … ВЫБОР id ИЗ lit : <присв> ; <вариант> <альт> ВСЕ ; КНЦ ;             (6)
 ⇒ … ВЫБОР id ИЗ lit : <слаг> * <степ> -> id ; …                           (7, 14)
 ⇒ … ВЫБОР id ИЗ lit : <элем> * <элем> -> id ; …                           (15)
 ⇒ … ВЫБОР id ИЗ lit : lit * lit -> id ; <вариант> <альт> ВСЕ ; КНЦ ;      (16)
 ⇒ … ВЫБОР id ИЗ lit : lit * lit -> id ; <спис_констант> : <опер> <альт> ВСЕ ; КНЦ ;   (10)
 ⇒ … <спис_констант> ⇒* lit , lit , lit , lit ; <опер> ⇒* lit -> id ;     (11 ×3, 6, 7, 13–16)
 ⇒ … lit , lit , lit , lit : lit -> id ; <альт> ВСЕ ; КНЦ ;
 ⇒ … lit , lit , lit , lit : lit -> id ; ИНАЧЕ <опер> ВСЕ ; КНЦ ;         (12)
 ⇒ … ИНАЧЕ lit -> id ; ВСЕ ; КНЦ ;                                        (6, 7, 13–16)
```

Итоговая сентенциальная форма:

```
ИМЕНА id , id ; lit -> id ; ВЫБОР id ИЗ lit : lit * lit -> id ;
lit , lit , lit , lit : lit -> id ; ИНАЧЕ lit -> id ; ВСЕ ; КНЦ ;
```

Сопоставление с фрагментом:

| Анализируемый фрагмент | Полученный синтаксический вывод |
|---|---|
| `ИМЕНА x, d;` | `ИМЕНА id , id ;` |
| `3 -> m;` | `lit -> id ;` |
| `ВЫБОР m ИЗ` | `ВЫБОР id ИЗ` |
| `2 : 7*4 -> d;` | `lit : lit * lit -> id ;` |
| `4, 6, 9, 11 : 30 -> d;` | `lit , lit , lit , lit : lit -> id ;` |
| `ИНАЧЕ 31 -> d;` | `ИНАЧЕ lit -> id ;` |
| `ВСЕ; КНЦ;` | `ВСЕ ; КНЦ ;` |

Вывод: фрагмент полностью выводим из начального символа `<программа>`, грамматика корректно описывает заданное подмножество языка.

### Примечания (можно дать после грамматики одним абзацем)

1. В формулировке задания ветвь иначе записана как `[иначе:]`; в примере программы двоеточия после `ИНАЧЕ` нет. Грамматика следует примеру программы; при необходимости правило (12) меняется на `<альт> ::= ИНАЧЕ : <опер> | ε`.
2. При необходимости обобщения: селектор `ВЫБОР` можно заменить на `<выраж>` (правило 8), а тело варианта/ветви иначе — на `<спис_опер>` (правила 10, 12), если допускается несколько операторов.
3. Проверки «все имена объявлены» (в примере `m` не объявлена — для Рапиры это допустимо) относятся к **семантическому** анализу, а не к синтаксическому.

Такой объём покрывает все элементы п. 7.6 задания и оставляет грамматику готовой для следующего раздела — построения LR-таблиц.
Вот содержимое ровно на одну сторону А4 — переписывай блоки в этом порядке, ничего не добавляя. Правила пиши по одному на строку, номер правила — на полях.

**Заголовок:** Построение грамматики подмножества языка Рапира

**1. Структура программы** (2–3 строки)

> Программа = описательная часть (директива ИМЕНА …;) + операторная часть (присваивания и оператор выбора) + КНЦ;
> Присваивание: 〈выраж〉 -> id. Выбор: ВЫБОР id ИЗ 〈варианты〉 [ИНАЧЕ …] ВСЕ

**2. Терминалы** (1–2 строки)

> T = {ИМЕНА, ВЫБОР, ИЗ, ИНАЧЕ, ВСЕ, КНЦ, ->, **, +, −, *, /, (, ), :, ,, ;, id, lit}
> (id — идентификатор, lit — константа; длина ≤ 6 и диапазон 0–255 проверяются на уровне сканера)

**3. Правила грамматики** (16 строк)

```
(1)  <программа> ::= <спис_опис> <спис_опер> КНЦ ;
(2)  <спис_опис> ::= <опис> | <спис_опис> <опис>
(3)  <опис> ::= ИМЕНА <спис_имен> ;
(4)  <спис_имен> ::= id | <спис_имен> , id
(5)  <спис_опер> ::= <опер> | <спис_опер> <опер>
(6)  <опер> ::= <присв> ; | <выбор> ;
(7)  <присв> ::= <выраж> -> id
(8)  <выбор> ::= ВЫБОР id ИЗ <спис_вар> <альт> ВСЕ
(9)  <спис_вар> ::= <вариант> | <спис_вар> <вариант>
(10) <вариант> ::= <спис_конст> : <опер>
(11) <спис_конст> ::= lit | <спис_конст> , lit
(12) <альт> ::= ИНАЧЕ <опер> | ε
(13) <выраж> ::= <слаг> | <выраж> + <слаг> | <выраж> − <слаг>
(14) <слаг> ::= <степ> | <слаг> * <степ> | <слаг> / <степ>
(15) <степ> ::= <элем> | <элем> ** <степ>
(16) <элем> ::= id | lit | ( <выраж> )
```

**4. Итог** (3–4 строки)

> G = ⟨T, N, P, ⟨программа⟩⟩; N — все нетерминалы правил (1)–(16).
> Все правила вида A → β ⇒ грамматика контекстно-свободная (тип 2 по Хомскому), форма Бэкуса–Наура.
> Левая рекурсия в (2), (5), (9), (11), (13), (14) сохранена намеренно: разбор по заданию — LR(k), для восходящего метода левая рекурсия допустима. Конфликтов сдвиг–свёртка нет (выбор в (12) определяется текущим символом: ИНАЧЕ либо ВСЕ).

**5. Проверка выводом** (10–12 строк) — таблица соответствия:

| Фрагмент программы | Терминальная цепочка |
|---|---|
| ИМЕНА x, d; | ИМЕНА id , id ; |
| 3 -> m; | lit -> id ; |
| ВЫБОР m ИЗ | ВЫБОР id ИЗ |
| 2 : 7*4 -> d; | lit : lit * lit -> id ; |
| 4, 6, 9, 11 : 30 -> d; | lit , lit , lit , lit : lit -> id ; |
| ИНАЧЕ 31 -> d; ВСЕ; КНЦ; | ИНАЧЕ lit -> id ; ВСЕ ; КНЦ ; |

Под таблицей — краткий вывод (2–3 строки):

```
<программа> ⇒(1) <спис_опис> <спис_опер> КНЦ; ⇒(2)–(4) ИМЕНА id , id ; …
⇒(5)–(16) ⇒ итоговая цепочка из таблицы. Цепочка выводима из <программа>,
следовательно грамматика построена верно.
```

---

**Как оформлять, чтобы выглядело «как в примере»:**
- номера правил (1)–(16) ставь на полях слева — так же, как в методичке;
- в выводе над стрелкой ⇒ подписывай номер применённого правила (или в скобках после неё);
- «→» в правилах и «->» (терминал-стрелка Рапиры) пиши заметно по-разному, чтобы преподаватель не спутал.

**Если не влезает** — режь в таком порядке: сначала убери пояснение под T (про сканер), затем строку про «ε = пусто», и в крайнем случае замени таблицу из п. 5 одной итоговой цепочкой:

```
ИМЕНА id , id ; lit -> id ; ВЫБОР id ИЗ lit : lit * lit -> id ;
lit , lit , lit , lit : lit -> id ; ИНАЧЕ lit -> id ; ВСЕ ; КНЦ ;
```

Полный по шагам вывод на лист не влезет и не нужен — в примере из презентации проверка тоже сведена к итоговому соответствию «фрагмент ↔ вывод».

Да, по Рапире — и это не догадка, а прямая логика методички. В предисловии практикума сказано: «Все работы взаимосвязаны – каждая последующая использует материал предыдущей, и, в сумме, позволяют получить рабочий компилятор». То есть восемь лабораторных — это поэтапная сборка того самого транслятора, который у вас в курсовой (сканер → классификация → грамматика → LR-таблицы → парсер → семантика → кодогенерация). Если в лабе делать другой язык, к лабе №3 всё равно придётся вернуться к Рапире, а к курсовой — переделывать всё заново. Берите сразу Рапиру — ваша грамматика и тестовые программы из курсовой переиспользуются в каждой следующей лабе.

Единственное уточнение, которое стоит сделать у преподавателя: не даст ли он отдельный вариант на лабу. По умолчанию — ваш вариант из курсовой.

Дальше — конкретика для вашего подмножества.

## 1. Что требуется в этой лабе (по вашей версии методички)

Вход: текстовый файл с программой на Рапире. Выход: **список токенов** (у вас версия лабы объединённая — в старой методичке это были две работы: «выделить лексемы» и «классифицировать»; у вас сразу обе). Плюс диагностика лексических ошибок и вывод на форму. Ограничение длины идентификатора в общем случае — 8, **но ваш вариант содержит иное: 6 символов** — действует вариант.

## 2. Спецификация лексики вашего подмножества

| Класс | Лексемы | Токен |
|---|---|---|
| Ключевые слова | ИМЕНА, ВЫБОР, ИЗ, ИНАЧЕ, ВСЕ, КНЦ | по одному токену на слово |
| Идентификаторы | рус/лат буквы, цифры, ≤ 6 симв., регистронезависимые | IDENT |
| Константы | целые 0–255 (1 байт) | NUM |
| Двулитерные разделители | `->`, `**` | ARROW, POWER |
| Однолитерные разделители | `+ − * / ( ) : ; ,` | PLUS, MINUS, STAR, SLASH, LPAR, RPAR, COLON, SEMI, COMMA |

Ключевые моменты, которые проверят на защите:

- **`->` и `**` — двулитерные разделители.** Это как раз тот класс из теории: «разделители, с которых начинается двулитерный разделитель». Сканер должен при встрече `*` или `-` заглянуть на следующий символ (принцип максимального поглощения): `2**3` → NUM, POWER, NUM; а `2* *3` → NUM, STAR, STAR.
- **Регистронезависимость:** `Выбор`, `ВЫБОР`, `выбор` — одно ключевое слово. Буфер приводится к верхнему регистру перед сравнением со словарём ключевых слов.
- **Лимиты — лексические ошибки:** идентификатор из 7+ символов («имя длиннее 6 символов»), константа > 255, посторонний символ (`@`, `#`, `"` — строк в подмножестве нет).

## 3. ДКА (что рисовать в отчёте)

По образцу рис. 1 методички — состояния S, ID, NUM, R с действиями Add / Next / Out / Clear:

```
S  --буква(рус/лат)-->  Add; Next --> ID
S  --цифра----------->  Add; Next --> NUM
S  --пробел, \n, \r-->  Next (остаёмся в S)
S  --*-->  след. литера '*' ? -> Out(**); Next; Next   : -> Out(*); Next
S  -->-->  след. литера '>' ?  -> Out(->); Next; Next   : -> Out(−); Next
S  --+ / ( ) : ; , /-->  Out(разделитель); Next

ID --буква, цифра-->  Add; Next (если буфер уже 6 литер -> ERROR: имя > 6)
ID --не буква/цифра--> Out(слово: ключевое? иначе id); Clear; в S (литеру вернуть)

NUM --цифра-->        Add; Next
NUM --не цифра-->     значение ≤ 255 ? Out(lit) : ERROR; Clear; в S
S, ID, NUM --прочая литера-->  ERROR (сообщение + строка/столбец)
```

Нюанс с возвратом литеры (символ, окончивший лексему, не потребляется) — в коде это `pos--` или проверка `i+1`.

```csharp
while (pos < text.Length) {
    char c = text[pos];
    if (char.IsWhiteSpace(c)) { pos++; continue; }

    if (char.IsLetter(c)) {                          // идентификатор / слово
        string buf = ReadWord(ref pos);              // буквы+цифры
        if (buf.Length > 6) Error("имя длиннее 6 символов", line, col);
        TokenType t = Keywords.TryGetValue(buf.ToUpper(), out var kw)
                      ? kw : TokenType.IDENT;
        tokens.Add(new Token { Type = t, Value = buf, ... });
    }
    else if (char.IsDigit(c)) {                      // константа
        string buf = ReadNumber(ref pos);
        if (int.Parse(buf) > 255) Error("константа вне диапазона 0–255", ...);
        tokens.Add(new Token { Type = TokenType.NUM, Value = buf, ... });
    }
    else if (c == '*' || c == '-') {                 // двулитерные
        char nx = pos + 1 < text.Length ? text[pos + 1] : '\0';
        if (c == '*' && nx == '*') { AddTok(POWER, "**"); pos += 2; }
        else if (c == '-' && nx == '>') { AddTok(ARROW, "->"); pos += 2; }
        else { AddTok(c=='*' ? STAR : MINUS, c.ToString()); pos++; }

    else if (Symbols.ContainsKey(c)) { AddTok(Symbols[c], c.ToString()); pos++; }
    else Error("недопустимый символ '" + c + "'", line, col);
```

Титульный лист → текст задания → программный код → тестовые примеры → скриншоты работы. ДКА нарисуйте явно (п. 3) — в содержании отчёта его нет, но по нему задают вопросы на защите.

**Вопросы самоконтроля — кратко, чтобы не плавать:**
- *Транслятор vs компилятор:* компилятор — частный случай транслятора; транслятор вообще — компилятор и интерпретатор (переводит и исполняет по ходу).
- *Этапы:* лексический → синтаксический → семантический → оптимизация → генерация кода.
- *Назначение лексанализа:* разбить поток символов на лексемы, выбросить пробелы/комментарии, заменить лексемы токенами фиксированной длины — упростить работу парсера.
- *Лексема:* структурная единица из элементарных символов, не содержащая других структурных единиц.
- *Ключевые слова vs имена:* для сканера ключевое слово — терминал из фиксированной таблицы (сравнение с образцом), идентификатор — класс по шаблону с занесением в таблицу имён; после распознавания оба становятся стандартными символами.

Важная связка с курсовой: ваш терминал `id` из грамматики = токен `IDENT`, `lit` = `NUM`, `**` = `POWER`, `->` = `ARROW`. Сканер, который вы напишете здесь, выдаёт ровно ту последовательность терминалов, на которой будет работать LR-анализатор из лаб №4 — поэтому и язык должен быть один.

Заменить можно спокойно: в задании нет ничего, привязанного к C# — код в методичке просто пример («например, можно так»). Вся логика (ДКА, токены, тесты) переносится один в один, меняется только синтаксис. Один реальный подводный камень в Java — **кодировка**: у вас русские ключевые слова и идентификаторы, поэтому и файл, и компиляция должны быть в UTF-8, иначе получите «недопустимый символ» на ровном месте.

## 1. Код на Java

**Файл `LexicalAnalyzer.java`** — сам сканер (архитектура: всё состояние в полях объекта, никаких глобальных переменных):

```java
import java.util.*;

public class LexicalAnalyzer {

    public enum TokenType {
        IMENA, VYBOR, IZ, INACHE, VSE, KNZ,      // ключевые слова
        ARROW, POWER,                            // ->  **
        PLUS, MINUS, STAR, SLASH,                // знаки операций
        LPAR, RPAR, COLON, SEMI, COMMA,           // разделители
        IDENT, NUM                               // классы лексем
    }

    public static class Token {
        public final TokenType type;
        public final String value;
        public final int line, col;

        public Token(TokenType type, String value, int line, int col) {
            this.type = type; this.value = value;
            this.line = line;   this.col = col;
        }
        @Override public String toString() {
            return String.format("%-7s %-7s строка %d, столбец %d", type, value, line, col);
        }
    }

    // Словарь ключевых слов: сравнение после приведения к верхнему регистру
    // (язык регистронезависимый: "выбор", "Выбор", "ВЫБОР" — одно слово)
    private static final Map<String, TokenType> KEYWORDS = Map.of(
        "ИМЕНА",  TokenType.IMENA,
        "ВЫБОР",  TokenType.VYBOR,
        "ИЗ",     TokenType.IZ,
        "ИНАЧЕ",  TokenType.INACHE,
        "ВСЕ",    TokenType.VSE,
        "КНЦ",    TokenType.KNZ
    );

    // Однолитерные разделители. '*' и '-' сюда сознательно НЕ входят:
    // с них начинаются двулитерные лексемы ** и ->
    private static final Map<Character, TokenType> SYMBOLS = Map.of(
        '+', TokenType.PLUS,  '/', TokenType.SLASH,
        '(', TokenType.LPAR,  ')', TokenType.RPAR,
        ':', TokenType.COLON, ';', TokenType.SEMI,
        ',', TokenType.COMMA
    );

    private static final int MAX_IDENT = 6;    // ограничение варианта задания
    private static final int MAX_CONST = 255;  // 1 байт

    private final String src;                 // входной текст
    private int pos = 0, line = 1, col = 1;    // позиция и координаты
    private final List<String> errors = new ArrayList<>();

    public LexicalAnalyzer(String src) { this.src = src; }
    public List<String> getErrors()  { return errors; }

    public List<Token> scan() {
        List<Token> tokens = new ArrayList<>();
        while (pos < src.length()) {
            char c = src.charAt(pos);
            if (Character.isWhitespace(c)) { advance(); continue; }  // пробелы отбрасываем

            int tl = line, tc = col;                                 // координаты начала лексемы

            if (Character.isLetter(c)) {                             // идентификатор / слово
                String lexeme = readWhile(Character::isLetterOrDigit);
                if (lexeme.length() > MAX_IDENT) {
                    error(tl, tc, "идентификатор длиннее " + MAX_IDENT + " символов: " + lexeme);
                    // лексема отброшена; сканирование продолжается
                } else {
                    TokenType t = KEYWORDS.getOrDefault(
                        lexeme.toUpperCase(Locale.ROOT), TokenType.IDENT);
                    tokens.add(new Token(t, lexeme, tl, tc));
                }
            }
            else if (Character.isDigit(c)) {                        // целая константа
                String lexeme = readWhile(Character::isDigit);
                long v = 0; boolean fits = true;
                try { v = Long.parseLong(lexeme); }
                catch (NumberFormatException e) { fits = false; }   // переполнение
                if (!fits || v > MAX_CONST)
                    error(tl, tc, "константа вне диапазона 0.." + MAX_CONST + ": " + lexeme);
                else
                    tokens.add(new Token(TokenType.NUM, lexeme, tl, tc));
            }
            else if (c == '*' || c == '-') {                         // двулитерные лексемы
                char next = pos + 1 < src.length() ? src.charAt(pos + 1) : '\0';
                if (c == '*' && next == '*') {                       // ** — возведение в степень
                    tokens.add(new Token(TokenType.POWER, "**", tl, tc));
                    advance(); advance();
                } else if (c == '-' && next == '>') {                // -> — стрелка Рапиры
                    tokens.add(new Token(TokenType.ARROW, "->", tl, tc));
                    advance(); advance();
                } else {                                             // одиночные * или -
                    tokens.add(new Token(c == '*' ? TokenType.STAR : TokenType.MINUS,
                                         String.valueOf(c), tl, tc));
                    advance();
                }
            }
            else if (SYMBOLS.containsKey(c)) {                       // однолитерный разделитель
                tokens.add(new Token(SYMBOLS.get(c), String.valueOf(c), tl, tc));
                advance();
            }
            else {
                error(tl, tc, "недопустимый символ: '" + c + "'");
                advance();
            }
        }
        return tokens;
    }

    // Чтение лексемы, пока литера удовлетворяет условию (Add; Next из ДКА)
    private String readWhile(java.util.function.IntPredicate cond) {
        StringBuilder sb = new StringBuilder();
        while (pos < src.length() && cond.test(src.charAt(pos))) {
            sb.append(src.charAt(pos));
            advance();
        }
        return sb.toString();
    }

    private void advance() {
        if (src.charAt(pos) == '\n') { line++; col = 1; }
        else col++;
        pos++;
    }

    // Развёрнутая диагностика: не останавливаемся на первой ошибке
    private void error(int l, int c, String msg) {
        errors.add(String.format("строка %d, столбец %d: %s", l, c, msg));
    }
}
```

```
VYBOR IDENT IZ

NUM COMMA NUM COMMA NUM COMMA NUM COLON NUM ARROW IDENT SEMI
```

Обратите внимание: в потоке токенов нет ни одного «сырого» слова `x`, `m`, `ВЫБОР` — всё заменено на стандартные символы. Это и есть главный тезис для вопроса «произойдёт ли уменьшение объёма текста после лексического разбора»: текст программы как последовательность токенов стал короче и однороднее (пробелы и переводы строк исчезли), но вместо этого появились таблицы имён и литералов — суммарный объём хранимой информации не уменьшается, меняется форма представления.

И связка с курсовой не потерялась: `IDENT` — это ваш `id` из грамматики, `NUM` — `lit`, `ARROW` — `->`, `POWER` — `**`. Этот сканер выдаёт ровно тот поток терминалов, на котором в лабе №4 будет работать LR-анализатор.

Держи. Одно важное предупреждение на секунду: в подмножестве из твоего задания (п. 7.6) условным оператором является только **ВЫБОР по константам** — оператора `ЕСЛИ` и знаков сравнения там нет, и в твою грамматику (1)–(16) они не входят. Поэтому ниже — расширение: 5 коротких программ с операторами условия в «диалекте задания» (с `;` после операторов) + 4 правила, которыми они добавляются в грамматику.

## Пять программ

**1. Минимальное ЕСЛИ — без ИНАЧЕ:**
```
ИМЕНА a;
5 -> a;
ЕСЛИ a > 3 ТО 1 -> a; ВСЕ;
КНЦ;
```

**2. ЕСЛИ с ИНАЧЕ:**
```
ИМЕНА a, b;
2 -> a; 5 -> b;
ЕСЛИ a > b ТО 1 -> b;
ИНАЧЕ 2 -> b;
ВСЕ;
КНЦ;
```

**3. Вложенные условия:**
```
ИМЕНА n, r;
5 -> n;
ЕСЛИ n > 3 ТО
  ЕСЛИ n = 5 ТО 50 -> r;
  ВСЕ;
ИНАЧЕ 0 -> r;
ВСЕ;
КНЦ;
```

**4. ВЫБОР ИЗ с логическими условиями** — рапировская цепочка «elseif» (условия проверяются сверху вниз, срабатывает первое истинное):
```
ИМЕНА a, c;
7 -> a;
ВЫБОР ИЗ
a > 10 : 1 -> c;
a > 5 : 2 -> c;
ИНАЧЕ 0 -> c;
ВСЕ;
КНЦ;
```

**5. Условие с арифметикой и `**`:**
```
ИМЕНА x, y;
2 -> x;
ЕСЛИ x**2 + 1 > 5 ТО 10 -> y;
ИНАЧЕ (x + 1)**2 -> y;
ВСЕ;
КНЦ;
```

## Расширение грамматики (если решите включить условия)

```
(6')  <опер> ::= <присв> ; | <выбор> ; | <усл> ;
(17)  <усл> ::= ЕСЛИ <лог_выраж> ТО <опер> ИНАЧЕ <опер> ВСЕ
             | ЕСЛИ <лог_выраж> ТО <опер> ВСЕ
(18)  <лог_выраж> ::= <выраж> <знак_ср> <выраж>
(19)  <знак_ср> ::= > | < | = | >= | <= | <>
```

Новые терминалы: **ЕСЛИ, ТО, >, <, =, >=, <=, <>**.

Для формы из примера 4 правило (8) обобщается: `<выбор> ::= ВЫБОР <селектор> ИЗ …`, где `<селектор> ::= id | ε`, а в `<вариант>` добавляется альтернатива `<лог_выраж> : <опер>`. Заметь: `lit : …` тогда может начинаться и как константа, и как условие — для LR(1) это не проблема (различие видно по символу после первого `lit`: `:` или знак сравнения), но на защите этот момент надо уметь объяснить.

## Что меняется в сканере

- в словарь ключевых слов: `ЕСЛИ → ESLI`, `ТО → TO`;
- три новых **двулитерных** разделителя: `>=`, `<=`, `<>` (к已有的 `->`, `**`) — при встрече `>`, `<`, `=` сканер смотрит на следующий символ; одиночный `=` — самостоятельный разделитель.

## `LexicalAnalyzer.java` (Java 8)

```java
import java.util.*;
import java.util.function.IntPredicate;

public class LexicalAnalyzer {

    public enum TokenType {
        IMENA, VYBOR, IZ, INACHE, VSE, KNZ,      // ключевые слова
        ARROW, POWER,                            // ->  **
        PLUS, MINUS, STAR, SLASH,                // знаки операций
        LPAR, RPAR, COLON, SEMI, COMMA,           // разделители
        IDENT, NUM                               // классы лексем
    }

    public static class Token {
        public final TokenType type;
        public final String value;
        public final int line, col;

        public Token(TokenType type, String value, int line, int col) {
            this.type = type; this.value = value;
            this.line = line;   this.col = col;
        }
        @Override public String toString() {
            return String.format("%-7s %-7s строка %d, столбец %d", type, value, line, col);
        }
    }

    // Словарь ключевых слов: сравнение после приведения к верхнему регистру
    // (язык регистронезависимый: "выбор", "Выбор", "ВЫБОР" — одно слово)
    private static final Map<String, TokenType> KEYWORDS = new HashMap<>();
    static {
        KEYWORDS.put("ИМЕНА",  TokenType.IMENA);
        KEYWORDS.put("ВЫБОР",  TokenType.VYBOR);
        KEYWORDS.put("ИЗ",     TokenType.IZ);
        KEYWORDS.put("ИНАЧЕ",  TokenType.INACHE);
        KEYWORDS.put("ВСЕ",    TokenType.VSE);
        KEYWORDS.put("КНЦ",   TokenType.KNZ);
    }

    // Однолитерные разделители. '*' и '-' сюда сознательно НЕ входят:
    // с них начинаются двулитерные лексемы ** и ->
    private static final Map<Character, TokenType> SYMBOLS = new HashMap<>();
    static {
        SYMBOLS.put('+', TokenType.PLUS);   SYMBOLS.put('/', TokenType.SLASH);
        SYMBOLS.put('(', TokenType.LPAR);   SYMBOLS.put(')', TokenType.RPAR);
        SYMBOLS.put(':', TokenType.COLON);  SYMBOLS.put(';', TokenType.SEMI);
        SYMBOLS.put(',', TokenType.COMMA);
    }

    private static final int MAX_IDENT = 6;     // ограничение варианта задания
    private static final int MAX_CONST = 255;    // 1 байт

    private final String src;                   // входной текст
    private int pos = 0, line = 1, col = 1;      // позиция и координаты
    private final List<String> errors = new ArrayList<String>();

    public LexicalAnalyzer(String src) { this.src = src; }
    public List<String> getErrors()  { return errors; }

    public List<Token> scan() {
        List<Token> tokens = new ArrayList<Token>();
        while (pos < src.length()) {
            char c = src.charAt(pos);
            if (Character.isWhitespace(c)) { advance(); continue; }  // пробелы отбрасываем

            int tl = line, tc = col;                                 // координаты начала лексемы

            if (Character.isLetter(c)) {                             // идентификатор / слово
                String lexeme = readWhile(new IntPredicate() {
                    public boolean test(int ch) { return Character.isLetterOrDigit(ch); }
                });
                if (lexeme.length() > MAX_IDENT) {
                    error(tl, tc, "идентификатор длиннее " + MAX_IDENT + " символов: " + lexeme);
                    // лексема отброшена; сканирование продолжается
                } else {
                    TokenType t = KEYWORDS.containsKey(lexeme.toUpperCase(Locale.ROOT))
                                ? KEYWORDS.get(lexeme.toUpperCase(Locale.ROOT))
                                : TokenType.IDENT;
                    tokens.add(new Token(t, lexeme, tl, tc));
                }
            }
            else if (Character.isDigit(c)) {                        // целая константа
                String lexeme = readWhile(new IntPredicate() {
                    public boolean test(int ch) { return Character.isDigit(ch); }
                });
                long v = 0; boolean fits = true;
                try { v = Long.parseLong(lexeme); }
                catch (NumberFormatException e) { fits = false; }   // переполнение
                if (!fits || v > MAX_CONST)
                    error(tl, tc, "константа вне диапазона 0.." + MAX_CONST + ": " + lexeme);
                else
                    tokens.add(new Token(TokenType.NUM, lexeme, tl, tc));
            }
            else if (c == '*' || c == '-') {                         // двулитерные лексемы
                char next = pos + 1 < src.length() ? src.charAt(pos + 1) : '\0';
                if (c == '*' && next == '*') {                       // ** — возведение в степень
                    tokens.add(new Token(TokenType.POWER, "**", tl, tc));
                    advance(); advance();
                } else if (c == '-' && next == '>') {                // -> — стрелка Рапиры
                    tokens.add(new Token(TokenType.ARROW, "->", tl, tc));
                    advance(); advance();
                } else {                                             // одиночные * или -
                    tokens.add(new Token(c == '*' ? TokenType.STAR : TokenType.MINUS,
                                         String.valueOf(c), tl, tc));
                    advance();
                }
            }
            else if (SYMBOLS.containsKey(c)) {                       // однолитерный разделитель
                tokens.add(new Token(SYMBOLS.get(c), String.valueOf(c), tl, tc));
                advance();
            }
            else {
                error(tl, tc, "недопустимый символ: '" + c + "'");
                advance();
            }
        }
        return tokens;
    }

    // Чтение лексемы, пока литера удовлетворяет условию (Add; Next из ДКА)
    private String readWhile(IntPredicate cond) {
        StringBuilder sb = new StringBuilder();
        while (pos < src.length() && cond.test(src.charAt(pos))) {
            sb.append(src.charAt(pos));
            advance();
        }
        return sb.toString();
    }

    private void advance() {
        if (src.charAt(pos) == '\n') { line++; col = 1; }
        else col++;
        pos++;
    }

    // Развёрнутая диагностика: не останавливаемся на первой ошибке
    private void error(int l, int c, String msg) {
        errors.add(String.format("строка %d, столбец %d: %s", l, c, msg));
    }
}
```

## `Main.java` (Java 8)

```java
import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.*;
import java.util.List;
import javax.swing.*;
import javax.swing.table.DefaultTableModel;

public class Main {
    public static void main(String[] args) throws IOException {
        // Java 11: Files.readString(...); Java 8: читаем байты и декодируем сами
        byte[] bytes = Files.readAllBytes(Paths.get("test.rap"));
        String src = new String(bytes, StandardCharsets.UTF_8);

        LexicalAnalyzer analyzer = new LexicalAnalyzer(src);
        List<LexicalAnalyzer.Token> tokens = analyzer.scan();
        List<String> errors = analyzer.getErrors();

        // Таблица токенов
        DefaultTableModel model = new DefaultTableModel(
            new Object[]{"Токен", "Значение", "Строка", "Столбец"}, 0);
        for (LexicalAnalyzer.Token t : tokens)
            model.addRow(new Object[]{t.type, t.value, t.line, t.col});
        JTable table = new JTable(model);

        // Панель диагностики
        JTextArea errArea = new JTextArea(
            errors.isEmpty() ? "Лексических ошибок нет" : String.join("\n", errors));
        errArea.setEditable(false);

        JSplitPane split = new JSplitPane(JSplitPane.VERTICAL_SPLIT,
            new JScrollPane(table), new JScrollPane(errArea));
        JFrame frame = new JFrame("Лексический анализатор (Рапира)");
        frame.add(split);
        frame.setSize(620, 520);
        frame.setLocationRelativeTo(null);
        frame.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        frame.setVisible(true);
    }
}
```

## Что именно изменилось (для понимания, не для отчёта)

| Было (Java 11+) | Стало (Java 8) |
|---|---|
| `Map.of("ИМЕНА", IMENA, ...)` | `static { KEYWORDS.put(...); }` |
| `Files.readString(path, UTF_8)` | `new String(Files.readAllBytes(path), UTF_8)` |
| `readWhile(Character::isLetterOrDigit)` | анонимный класс `IntPredicate` (можно и лямбду `ch -> Character.isLetterOrDigit(ch)` — она в Java 8 работает, оставил анонимный класс для полной одинаковости со скриншотов разных сред) |

## Запуск — тот же

```
javac -encoding UTF-8 LexicalAnalyzer.java Main.java
java Main
```

`test.rap` в UTF-8 — по-прежнему главное условие, от версии Java не зависит. Поведение, тесты, эталонная последовательность токенов — идентичны, так что в отчёт подойдёт любой из двух вариантов кода.
